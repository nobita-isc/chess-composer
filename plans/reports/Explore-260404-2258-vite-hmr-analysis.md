**Key Issues Identified:**
- **No explicit HMR configuration** - Relies on Vite defaults
- **PWA plugin with autoUpdate** - May conflict with HMR if service worker caches static assets aggressively
- **Cache-Control header set to 'no-store'** in dev server (good) but PWA precaching may override
- **No middleware configuration** - Could cause issues with Hono backend communication

## Root Causes of Hot-Reload Issues

### Primary Issues:
1. **Service Worker Caching** - PWA plugin with `registerType: 'autoUpdate'` and Workbox precaching aggressive caching may block HMR updates
2. **Missing HMR Configuration** - No explicit `server.hmr` block in Vite config to override defaults
3. **CORS Mismatch** - Server allows port 5173 but client runs on 3000; HMR WebSocket may fail
4. **No Client-Side Hot Reload Handlers** - Application doesn't use `import.meta.hot.accept()` for HMR

### Secondary Issues:
5. **Port Assumptions** - Vite may default to 5173 for HMR socket if 3000 unavailable
6. **Proxy Configuration** - API proxy to `:3001` works but no middleware for HMR path exclusion

## Recommendations

### Quick Fixes (Priority 1):
```javascript
// Add to vite.config.js
server: {
  hmr: {
    host: 'localhost',
    port: 3000,
    protocol: 'ws'
  }
}
```

### Medium Priority (Priority 2):
- Update server CORS to explicitly allow HMR port
- Configure Workbox to NOT precache `*.js` files (let HMR handle them)
- Add service worker update check on app startup

### Long Term (Priority 3):
- Implement `import.meta.hot.accept()` in critical modules
- Use Vue/React HMR if framework adoption happens
- Set up dedicated HMR dev tools
